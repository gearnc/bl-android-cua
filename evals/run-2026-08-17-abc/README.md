# A/B/C, 17 August 2026 — 36 runs at `7524d3a`

6 apps × 3 arms (**hybrid / bare / raw**) × 2 replicates, Normal capability, ~30
machine-verifiable tasks each, one app per child session. **No `acli` arm was run and no archived
`acli` number is quoted here.** Hybrid/bare is comparable with `evals/baseline-2026-08/`; `raw`
has history only in the three-arm matrices of 14–16 August, so its ratios are quoted inside this
run.

## What was measured

- plugin: `main` @ `7524d3a` (the merge of #24, the batch-hint PR), containing **both**
  `skills/android-hybrid-navigation` and `skills/android-raw-navigation` — verified by grepping a
  throwaway child's plugin cache for the raw skill's `SKILL.md` and printing its `ui.py` wrapper,
  not assumed from the snapshot date
- emulator: Android 14 / API 34, 720x1280 @320dpi, F-Droid APKs preinstalled
- apps: markor, amaze (Views), seal, unitto (Compose), joplin, lesspass (React Native)
- arms differ by exactly one paragraph (`suites.ARM_HYBRID` / `ARM_BARE` / `ARM_RAW`): `bare` is
  denied both skills and `hd`, `raw` is denied only `android-hybrid-navigation`/`hd` and told to
  read `android-raw-navigation`'s SKILL.md itself. Neither the wrapper nor any command was pasted
  into a prompt.
- the plugin was not modified between launching the matrix and collecting it. `swipe --until`,
  `evals/bench_scroll_hunt.py` and the report's hunt section, all in the same PR as this archive,
  were written **after** collection and are NOT in the measured revision.

## Validity

- **bare arm's perception mode**: the flattering framing this time — 9/12 bare runs did visual
  CUA (≥20 screenshots, median 84), 1/12 improvised tree tooling, 2 in between. So hybrid/bare
  here is mostly *skill vs. visual computer use*.
- **bare rederivation**: 3/12 bare runs wrote or ran a dump wrapper of their own, first at
  command 3–4 (amaze|bare|1, lesspass|bare|1, markor|bare|1) — the quantity `raw` vs `bare`
  prices happened in a quarter of the cells.
- **raw arm adoption**: 12/12 used the method (865 wrapper/`uiautomator dump` invocations, first
  at command 2–12). **Contamination: 0/12 invoked `hd`.** No cell was dropped.
- **bypass**: runs writing device state directly — 5/12 hybrid, 3/12 bare, 6/12 raw; no arm did
  materially less work.
- **dump preflight**: `python3 evals/test_dumps.py markor amaze seal unitto joplin lesspass`
  returned rc=0 with no `problems` for all six apps of the matrix, each launched first.
- every cell returned structured output; 36/36 collected, no relaunches.

## Mechanism (what the PR acts on)

Price per look is no longer the story: hybrid pays **348** perception tokens a look against the
raw wrapper's **288**. The gap is the *number* of turns — hybrid takes **4.32 looks per task**
against raw's **2.73** and chains **1.40 actions per look** against raw's **1.96**, and across
the hybrid/bare cells one extra look per task prices at **0.043 ACU per task** (~1.2 ACU a run).

One concrete slice of that looking is scrolling: **72 commands inside 24 swipe-then-look hunts
across 10/12 hybrid runs**, each look answering nothing but "did the row arrive yet?". The PR
adds `hd swipe <dir> --until PAT`, which runs that loop in one process, silently re-caches
between swipes, prints only the lines that answer with `hd tap`-able indexes, and stops early
when the list stops moving. `evals/bench_scroll_hunt.py` prices it on real scrollable screens.

Unfixed and priced here for the next PR: 106 of the hybrid arm's 305 look-only commands (12/12
runs) were still a look followed by nothing but `hd tap <index>` even though `hd tap "PAT"` took
27% of taps, and 79 focus-hunting commands survive in 11/12 runs.
