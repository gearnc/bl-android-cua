# A/B/C, 14 August 2026 — 36 runs

6 apps × 3 arms (hybrid / bare / acli) × 2 replicates, Normal capability, ~30 machine-verifiable
tasks each, one app per child session. This is the first run with a third arm, so **hybrid/bare is
comparable with `evals/baseline-2026-08/`, acli has no history** — do not read an acli number
against the archived two-arm baselines.

## What was measured

- plugin: `main` @ `def39f8` (verified in the child snapshot's plugin cache, not assumed)
- accessibility-cli: `0.1.0` @ `03cfeb3db1ecd37375f370edfe86b8ffbfa9037f`, `cargo install`ed by the
  org blueprint
- emulator: Android 14 / API 34, 720x1280 @320dpi, F-Droid APKs preinstalled
- apps: markor, amaze (Views), seal, unitto (Compose), joplin, lesspass (React Native)

## Headline

Ratios against bare — ACU: hybrid **1.02x**, acli **1.18x**. Perception tokens: hybrid **1.02x**,
acli **1.22x**. Iterations: hybrid **1.02x**, acli **1.14x**. Tasks done: hybrid **0.99x**, acli
**0.99x**. Screenshots (mean): hybrid 6.0, bare 11.0, acli 17.4. `report.md` is the full writeup.

At equal reliability all three arms cost about the same to run and acli costs ~20% more; the
arms differ in the tail and in what they spend their looks on, which is what `report.md` decomposes.

## Validity

- every one of the 36 cells settled and returned structured output; none was graded from prose
- every matrix app dumped cleanly (`test_dumps.py` rc=0) and `test_acli.py` reported
  `problems=none` for all six apps before launch
- **bare-arm mode**: not screenshot CUA. 3/12 bare runs improvised tree tooling (≤5 screenshots),
  1/12 did visual CUA (≥20), 8/12 in between; median 10 screenshots over ~30 tasks. The honest
  framing is *skill vs. agent-improvised tree tooling*.
- **acli adoption**: 12/12 acli runs invoked the binary — no cell dropped, so the arm measures
  accessibility-cli and not a fallback
- **bypass balance**: runs writing device state directly are 5/12 hybrid, 5/12 bare, 5/12 acli —
  balanced, so the ACU comparison stands
- the plugin was not modified and acli was not rebuilt between launch and collection; the
  focused-field change in this PR was written after collection finished

## Files

- `runs.json` — cell → session id (the sessions are the ultimate audit trail)
- `state.json` — final state, ACU and completion detail per cell
- `metrics.json` — ACU, perception/context/billed tokens, iterations, exec calls, screenshots
- `tasks.json` — n_done / n_partial / n_failed per cell
- `bypass.json` — UI-bypassing shortcut commands per cell
- `exec_commands.json` — every captured `shell_process_started` command, per cell; the adoption,
  verb-mix and focus-hunt sections of the report are derived from it
- `report.md` — generated by `evals/make_report.py` from the files above
